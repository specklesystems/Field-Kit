# Shape a task

Ask or infer, then state:

- **Outcome:** who benefits and what becomes possible?
- **Input:** what public data, model or event begins the workflow?
- **Transformation:** what must the software do?
- **Output:** what tangible result should appear?
- **Evidence:** how will a person know the result is correct?
- **Boundary:** what is explicitly outside this attempt?

Choose the smallest FieldKit project that owns the work. Propose one thin
slice and its success check. Surface assumptions before implementation. Avoid
turning an exploratory workshop idea into production architecture by default.

If the implementation route is unclear—or the work will be shared, repeated,
automated, write data, or support a consequential decision—continue with
`../choose-a-route/SKILL.md`. A small, read-only experiment does not need that
extra ceremony.
